# DEF-2026-003: `${VAR:-default}` environment-variable expansion is not implemented, contrary to the documentation


| Field | Content |
|------|------|
| **Defect ID** | DEF-2026-003 |
| **Status** | Open |
| **Severity** | Minor (no `${}` placeholders currently exist in `config/config.yaml`, so it is not actually triggered) |
| **Priority** | P3 |
| **Detection Phase** | Unit (source review during test authoring) |
| **Requirement / Test** | REQ-config / `tests/test_config.py` (pinned via a "literal-preserved" behavior snapshot) |
| **Reporter / Date** | Test Engineering (AI-assisted, human-reviewed) / 2026-07-09 |
| **Assignee** | Unassigned |

## 1. Environment
`src/config/config_manager.py`; the README sections on "config-driven" behavior and "configuration override precedence".

## 2. Preconditions
`config.yaml` contains a placeholder of the form `${VAR:-default}`.

## 3. Steps to Reproduce
1. Write `database_url: ${DATABASE_URL:-postgresql://localhost/rag}` in config.yaml.
2. Set the `DATABASE_URL` environment variable and start the service.

## 4. Expected (per README)
The placeholder expands to the environment-variable value (or the default).

## 5. Actual
The config layer only calls `yaml.safe_load`; there is no expandvars / envsubst logic anywhere in src/, main.py, app.py, or scripts/, so the placeholder enters the config as a **literal string**.

## 6. Evidence
`tests/test_config.py` pins the "`${VAR:-default}` preserved literally" behavior via snapshot; `grep -rn 'expandvars|envsubst' src/ main.py app.py` returns nothing.

## 7. Root Cause
The README describes the intended design (aligned with MCP_Center), but the expansion logic is not yet implemented; deployments currently run with "hardcoded values + `.env`", so the gap has not surfaced.

## 8. Resolution
One of two options: (a) perform regex-based `${VAR:-default}` expansion in `_load_config` after reading the file and before `yaml.safe_load`, and add the corresponding REQ/TC; or (b) correct the README to list this as a planned feature. The README has been annotated for now (see commit).
