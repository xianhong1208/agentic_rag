## 1. Environment
`src/domain/exceptions.py:76` (`FolderNotFoundError`) and `:184` (`QueryExecutionError`).

## 2. Preconditions
The caller constructs the exception with `folder_id=0` (in practice DB folder ids start at 1, so this is not triggered today).

## 3. Steps to Reproduce
1. `FolderNotFoundError(folder_id=0)`.
2. Inspect the message / details.

## 4. Expected
The identifier should be `0` (an `is not None` check).

## 5. Actual
- `FolderNotFoundError`: `folder_id if folder_id else folder_name` makes the identifier `None`.
- `QueryExecutionError`: `if folder_id:` means `folder_id=0` is not written into details.

## 6. Evidence
Relevant cases in `tests/test_exceptions.py`; see also SPEC-exceptions, Section 4.

## 7. Root Cause
A truthiness check is used where an `is not None` check is required.

## 8. Resolution
To fix: change both sites to `if folder_id is not None`. Low-risk, purely defensive fix; add a `folder_id=0` assertion when fixing.

### Related observations (not defects; design-risk register)

1. The domain `FileNotFoundError` at `exceptions.py:80` shadows the Python built-in exception of the same name. After a caller does `from src.domain.exceptions import FileNotFoundError`, the semantics of `except FileNotFoundError` for OS errors change. Consider renaming it in the future (e.g. `RagFileNotFoundError`) or documenting the import convention.
2. The `estimate_tokens` docstring at `hierarchy.py:40` states "1 English word ≈ 1.3 tokens", but the implementation uses 0.3 tokens/char, so the description and implementation disagree (the test follows the implementation); the docstring should be corrected.
