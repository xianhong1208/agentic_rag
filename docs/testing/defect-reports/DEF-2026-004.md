## 1. Environment
`src/config/config_manager.py::_load_config` (around L145-158).

## 2. Preconditions
Config loading is invoked with a non-existent path.

## 3. Steps to Reproduce
1. `get_config("config/not_exist.yaml")`.

## 4. Expected (per docstring)
Raise `FileNotFoundError` so the startup flow fails loudly.

## 5. Actual
The `raise` sits inside a try block and is caught and swallowed by `except Exception`, so the caller receives `None` and an empty `_config`. When the config path is mistyped, the service may start silently with an empty configuration, deferring the failure.

## 6. Evidence
The file-not-found case in `tests/test_config.py` (behavior snapshot); code review.

## 7. Root Cause
The exception-handling scope is too broad (`except Exception` wraps the deliberate `raise`).

## 8. Resolution
To fix: move the "file not found" check out of the try block, or add `except FileNotFoundError: raise` before `except Exception`. Flip the test assertion when fixing.
