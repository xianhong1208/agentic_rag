# DEF-2026-001:`_parse_db_url` 未對帳密做 percent-decoding

## 1. 環境
所有部署環境;`src/utils/db_bootstrap.py::_parse_db_url`。

## 2. 前置條件
`DATABASE_URL` 的帳號或密碼含需 percent-encoding 的字元(如 `@`、`:`、`/`、`%`)。

## 3. 重現步驟 (Steps to Reproduce)
1. 設 `DATABASE_URL=postgresql://u%40ser:p%40ss@host:5432/dbname`(帳密含 `@` 的合法編碼)。
2. 啟動服務,走到 `db_bootstrap` 建庫 / 連線流程。

## 4. 預期結果 (Expected)
`_parse_db_url` 應以 `urllib.parse.unquote` 解碼 username / password,
psycopg2 收到明文 `u@ser` / `p@ss`,連線成功。

## 5. 實際結果 (Actual)
`urlparse` 的 username/password 保持 `u%40ser` / `p%40ss` 原樣傳給 psycopg2,登入失敗。

## 6. 佐證 (Evidence)
`tests/test_db_bootstrap.py` 中 percent-encoding 案例以「現行行為快照」方式鎖定
(測試標註此為已登記缺陷);`docs/testing/specs/SPEC-db-bootstrap.md` 第 4 節備註。

> 參考:MCP_Center 曾修過同型問題(commit「`DATABASE_URL` 帳密含百分比編碼可正常開機」),
> 修法可直接沿用。

## 7. 根因分析 (Root Cause)
`urllib.parse.urlparse` 依 RFC 回傳的 `username`/`password` 為原始(仍編碼)字串,
實作時未加 `unquote`。

## 8. 處置 / 修復 (Resolution)
待修:`_parse_db_url` 對 username/password 補 `urllib.parse.unquote`;
修復時同步把 TC-db-bootstrap-03 從「行為快照」改為「解碼後斷言」,並跑回歸。
