# DEF-2026-001: `_parse_db_url` does not percent-decode credentials


| Field | Content |

## 1. Environment
All deployment environments; `src/utils/db_bootstrap.py::_parse_db_url`.

## 2. Preconditions
The username or password in `DATABASE_URL` contains characters that require percent-encoding (e.g. `@`, `:`, `/`, `%`).

## 3. Steps to Reproduce
1. Set `DATABASE_URL=postgresql://u%40ser:p%40ss@host:5432/dbname` (credentials contain a legitimately encoded `@`).
2. Start the service and reach the `db_bootstrap` database-creation / connection flow.

## 4. Expected
`_parse_db_url` should decode the username / password with `urllib.parse.unquote`, so psycopg2 receives the plaintext `u@ser` / `p@ss` and connects successfully.

## 5. Actual
The username/password from `urlparse` are passed to psycopg2 verbatim as `u%40ser` / `p%40ss`, and authentication fails.

## 6. Evidence
The percent-encoding case in `tests/test_db_bootstrap.py` is pinned as a "current-behavior snapshot" (the test notes this is a registered defect); see also `docs/testing/specs/SPEC-db-bootstrap.md`, Section 4.

> Reference: MCP_Center previously fixed the same class of issue (commit "`DATABASE_URL` credentials with percent-encoding boot correctly"); that fix can be reused directly.

## 7. Root Cause
The `username`/`password` returned by `urllib.parse.urlparse` are the raw (still-encoded) strings per RFC, and the implementation did not apply `unquote`.

## 8. Resolution
To fix: apply `urllib.parse.unquote` to username/password in `_parse_db_url`. When fixing, also change TC-db-bootstrap-03 from a "behavior snapshot" to a "decoded assertion" and run the regression suite.
