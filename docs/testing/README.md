# Agentic RAG — Testing Process and Documentation


This directory defines the **testing process, documentation standards, and traceability** of the Agentic RAG MCP Server. The goal: every test case
traces back to a specific functional requirement, and every code change has a corresponding test guarding it.

The testing methodology follows the [FuSa Group "Complete Guide to Software Testing Methodologies"](https://fsg.tw/software-testing-methodologies-guide-a-high-level-overview/)
(shift-left testing, the five test-type levels, functional/non-functional classification, exit criteria).

## Process Overview (shift-left: requirement → case → script → guard)

```
Requirement (Spec)  ──►  Test Case  ──►  Test Script (pytest)  ──►  Coverage Threshold
   REQ-xxx               TC-xxx              test_*.py               fail_under (CI planned)
     │                     │                    │
     └─────────────────────┴────────────────────┘
              Traceability
```

1. **Requirements first (shift-left)**: every feature first gets a `REQ-<module>-<number>` requirement in `specs/`.
2. **Cases based on requirements**: every `TC-<module>-<number>` in `test-cases/` notes which `REQ` it verifies.
3. **Scripts implement cases**: the docstring of each test function in `tests/test_*.py` notes its `TC` number.
4. **Coverage guard**: `uv run pytest --cov` exits non-zero below the threshold; the CI pipeline is on the ROADMAP.

## Standard Process for Adding a Test

1. Add or update a `REQ-<module>-<number>` in `specs/SPEC-<module>.md` (using the template).
2. Write the corresponding `TC-<module>-<number>` in `test-cases/TC-<module>.md` (input / steps / expected result).
3. Implement it in `tests/test_<module>.py`, noting the TC number in the docstring.
4. Run `uv run pytest --cov` to confirm all green and that coverage does not drop.
5. Update this README's matrix and [COVERAGE.md](COVERAGE.md).
